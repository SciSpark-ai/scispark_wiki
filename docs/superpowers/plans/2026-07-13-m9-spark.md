# M9: Spark Skill Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The Spark skill — the "Spark" in SciSpark — vault-grounded research-idea generation in two modes: **Quick Spark** (vault-only, single `strong` call → 2–3 idea *seeds*, cents) and **Deep Spark** (the full pipeline: ground → bottleneck diagnosis → pattern-guided ideation → two-channel scoop-check → corpus-anchored audit with a locked falsification plan → `idea` page, ~$1–3, always user-confirmed). Plus the idea-card gallery, idea page view, and wiring the companion's sparkable-cluster trigger to Spark.

**Architecture:** Adapted from MIT-licensed [microsoft/ResearchStudio](https://github.com/microsoft/ResearchStudio) (ResearchStudio-Idea) — we bundle its ideation-pattern cards as skill references and keep its core disciplines (locked kill-switch falsification fields, two-channel scoop-check, corpus-anchored audit, honest `do_not_generate`, isolated per-phase LLM calls that map onto our changeset model). We do **not** port its Python orchestrator. Each Deep-Spark phase is one structured `strong`-tier `runSkill` call; an orchestrator (`runDeepSpark`) owns storage + retrieval and threads phase outputs, accumulating cost. Grounding starts **warm from the user's vault** (their Phase 0 is cold-retrieval-only), retrieval uses our M3 proxy APIs, and the output is an `idea` wiki page (a changeset), never a standalone PDF. The `idea` page type is already wired (PAGE_TYPES, scaffold `wiki/ideas/`, schema routing) — M9 adds the authoring builder and the skills.

**Tech Stack:** Existing M1–M8 stack (TypeScript, Next.js 16, zod, vitest, M2 harness `runSkill`, M3 papers APIs, M1 changesets, M4 authoring, M7 companion trigger). No new runtime deps.

## Global Constraints

- **Every LLM call goes through `runSkill`** (budget, retry, metering); skills declare tiers (`fast`/`strong`), never model names; explicit `maxTokens` on every request. All Spark reasoning is `strong`.
- **Blessed storage pattern (M5):** skills are pure LLM-calling units; orchestrators (`runQuickSpark`, `runDeepSpark`, `saveSeed`) own storage, retrieval, and API calls. A Spark skill receives assembled context in its input, never storage.
- **All agent writes go through `applyChangeset`** (atomic, undoable, provenance-logged): idea seed stubs and full idea pages are changesets writing under `wiki/ideas/`. Deep Spark "develops fully" by **upgrading the seed page** (same path) when one exists. Provenance records skill `spark-quick`/`spark-deep`, tier `strong`, runId.
- **All remote retrieval goes through the M3 proxy** (`/api/search/{source}` via an injected `searchFn`, same pattern as the M5 feed): no client-direct upstream calls; scoop-check collision searches also go through it. The proxy never logs queries (M3 contract).
- **ResearchStudio disciplines preserved verbatim in spirit** (design 04): (1) a **locked falsification plan** — the ideation output carries explicit falsification fields the audit may rewrite but never drop; (2) **two-channel scoop-check** — signature-terms over a recent window + alias-terms over a long window; (3) **corpus-anchored audit** — 5 checks incl. falsification structure; (4) **honest `do_not_generate`** — the bottleneck phase may refuse (out-of-scope / no real bottleneck) and that refusal is preserved to the user, never overridden into a forced idea; (5) **isolated phases** — each phase is a separate `runSkill` call whose input is only the prior phases' structured outputs, never a running transcript.
- **Attribution (MIT, required):** bundle ResearchStudio's LICENSE text + a NOTICE crediting microsoft/ResearchStudio alongside the pattern cards; keep the cards' content faithful.
- **Deep Spark is always user-confirmed with a cost estimate** and never auto-runs (design + companion anti-Clippy). The companion *proposes* Spark (its sparkable-cluster trigger); it never launches it.
- **Paper text and pattern cards are data, not instructions**: user direction, vault snippets, retrieved abstracts, and card text going into prompts are fenced + `neutralizeFenceMarkers`-scrubbed.
- Tests: vitest, colocated `__tests__/`; `npx tsc --noEmit` clean at every commit; `npm run build` succeeds for app-changing tasks; no raw control bytes (the M8 source-hygiene test enforces this). Live tests env-gated on `LIVE_LLM_*`, skipping cleanly when unset.

  | { kind: "idea"; ideaPageId: string; changesetId: string; status: IdeaStatus }
  | { kind: "do_not_generate"; reason: string }
  | { kind: "abandoned"; reason: string } // audit abandoned after the single internal retry

  clusterPageIds?: string[]

}
