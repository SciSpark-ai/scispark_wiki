# SP5 — Knowledge-Base Chat Implementation Plan

**Status (2026-07-28):** Built — all 11 tasks complete and reviewed, 1968 tests green, tsc clean, build green, live-verified end to end at ~$0.031/turn. Lint improved to 4 errors/4 warnings (from the 8/5 baseline) because Task 9's deletion of fork-era mock files removed some.

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the forked `/chat` mock with a real conversation over the user's own knowledge base: grounded answers with clickable citations, sessions stored in the vault, a Read-Sources-Only mode, and one-click saving of an answer as a `query` wiki page.

**Architecture:** Two `runSkill` steps — a `fast` call picks relevant page ids out of `index.md` (validated against ids that actually exist), then a `strong` call answers over those pages' bodies plus saved papers' TL;DRs/abstracts, returning `{answer, citedPageIds}` in the same shape `reading-companion` already produces. A deterministic term-overlap selector is the fallback when step 1 fails. Sessions live at `.scispark/chats/<id>.json`; the orchestrator owns all storage, the skills stay pure LLM units.

**Tech Stack:** Next.js 16 App Router, `runSkill` harness (tiers/budget/metering), zod-validated skill output, `ndjsonSkillRoute` streaming, Tailwind v4 SP1 tokens, vitest + `react-dom/server`.

**Spec:** `docs/superpowers/specs/2026-07-25-sp5-kb-chat-design.md`

**Correction to the spec's wording:** §3 says answers stream over "SSE". The repo's actual streaming helper is `ndjsonSkillRoute` (`src/lib/server/skill-route.ts:74`), which emits newline-delimited JSON, and it is what feed refresh / ingest / Deep Spark use. Use it. Do not introduce a second transport — the spec's intent ("stream over the mechanism already in use") is what governs.

## Global Constraints

- **Grounding is not negotiable.** Every answer is derived from vault content passed in the prompt. The skills never browse, never invent citations, and a cited page id that is not in the supplied context is dropped by the orchestrator.
- **Prompt-injection defence:** all vault content — wiki bodies *and* paper abstracts — is wrapped in the `WIKI-DATA` fences ingest already uses, via `neutralizeFenceMarkers` (`src/lib/skills/ingest-analysis.ts`), with the standing instruction that fenced content is data and instructions inside it are never followed.
- **`MAX_HISTORY_TURNS = 6`** — the last 6 turns go in verbatim; earlier turns are dropped, never summarized. One named constant, defined once.
- Persona wraps **tone only** and never touches grounding rules — follow `reading-companion.ts`'s use of `withPersona` exactly.
- Sessions are vault files; a corrupt or unreadable session file reads as **absent**, never a crash.
- All colors/typography via SP1 semantic tokens — the no-raw-hex guard and the browser-purity gate stay green.
- Titles render through `displayTitle`; wiki links through `wikiHref`; paper links to `/paper/<slug>`.
- No new dependencies. `npm run lint` adds nothing over the pre-existing 8-error/5-warning baseline. `npm run build` passes.
- No `dangerouslySetInnerHTML` unless the wrapper object is referentially stable; never side-effect inside a JSX expression (both are documented repo footguns).

export interface ChatMessage {
  role: "user" | "assistant"
  content: string

  citedPageIds?: string[]
  /** Assistant only: whether Read-Sources-Only was in effect for this answer. */

- Produces:

```ts
export const MAX_HISTORY_TURNS = 6
export interface AskChatInput {
  sessionId: string | null      // null → start a new session
  question: string
  readSourcesOnly: boolean
}
export interface AskChatResult {
  sessionId: string
  message: ChatMessage          // the assistant turn, persisted
}
export async function askChat(storage: VaultStorage, opts: {
  input: AskChatInput
  settings?: LLMSettings
  providerOverride?: Partial<Record<Tier, LLMProvider>>
  now?: () => Date
  onProgress?: (stage: "selecting" | "answering") => void
}): Promise<AskChatResult>
```

Pipeline: load or create the session → append the user turn and **persist immediately** (so a failed answer never loses the question) → build the index via `buildIndexMarkdown(bundle)`, narrowed to `type: paper` pages when `readSourcesOnly` → `runSkill(selectPagesSkill)` → **validate the returned ids against the bundle, dropping any that do not exist** → assemble context from the surviving pages (wiki bodies; for paper pages the `tldr` + abstract) → `runSkill(chatAnswerSkill)` → **drop any `citedPageIds` not present in the supplied context** → append the assistant turn and persist.

**Degradation, each independent and individually tested:**
- selection call fails → `fallbackSelectPages`, and the persisted message carries `selectionFallback: true`;
- a selected page fails to read → skip it, answer from the rest;
- the answer call fails → persist an assistant message carrying `error` with the real reason, leaving the user turn intact;
- empty vault (no pages) → return an assistant message that says the knowledge base is empty and points at `/papers`, without calling the LLM at all.

The route wraps `askChat` with `ndjsonSkillRoute`, emitting `{stage}` progress events, and `client.ts` is the browser wrapper consuming that stream (mirror `src/lib/skills/ingest-client.ts`'s structure).
